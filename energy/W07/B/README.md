# Formal proofs, controls and engineering correspondence

The core lock is [proof_lock.json](proof_lock.json). [protocol.md](protocol.md) identifies the prospective claims; [LITERATURE.md](LITERATURE.md) maps them to original publications. [claims.csv](claims.csv) states the scope of each conclusion. The core contains 31 theorems. A separately locked [real-infimum addendum](addendum/Infimum.lean) contains four more. All source is editable. The W07-A and W07-E implementations share the engineering specification with the formalization.

From the W07 root, use Python 3 and the pinned Lean toolchain. The standard library suffices for the finite controls and correspondence scripts. The exact simulation archive is required for the A/E checks.

    python3 B/exact_controls.py > /tmp/crgc-w07-exact.json
    cmp /tmp/crgc-w07-exact.json B/results/exact_controls.json
    python3 B/correspondence.py A A/results/records.json > /tmp/crgc-w07-A.json
    cmp /tmp/crgc-w07-A.json B/results/engineering-A.json
    python3 B/correspondence.py E E/results/kernels.json.gz > /tmp/crgc-w07-E.json
    cmp /tmp/crgc-w07-E.json B/results/engineering-E.json
    python3 B/verify.py --lean "$LEAN_BIN" --packages "$PACKAGES" --out /tmp/crgc-w07-proof --replay-oleans
    python3 B/addendum/verify_addendum.py --lean "$LEAN_BIN" --packages "$PACKAGES" --out /tmp/crgc-w07-infimum

The Lean output directories must be empty at entry. The exact engineering receipt includes archived artifact digests; timing fields inside regenerated A records can change that digest. After a cold computational rerun verify substantive counts and separately record the digest of that rerun. For the observed engineering source and artifacts the checked receipts reproduce byte for byte.

LEAN_BIN points to the executable from [formal/lean-toolchain](formal/lean-toolchain). PACKAGES is the absolute path to a clean Lake packages directory with the nine source revisions in [formal/lake-manifest.json](formal/lake-manifest.json) and their matching built libraries. A new machine can populate a disposable project from formal/lakefile.toml, the lock and the toolchain with elan, Git, Lake and mathlib's release cache. This build reused existing prebuilt package libraries after checking their tracked source checkouts. The compiler, packages and upstream compiled libraries remain external dependencies. The verifier builds project modules in fresh temporary directories, audits theorem axioms and dependency edges, requires specific negative diagnostics and replays the local OLean declarations with the same compiler's leanchecker. No independent kernel or cold rebuild of all upstream libraries was run. Absolute timing includes preflight, builds, replay and exact arithmetic; wall time depends on host load.

## Source map and interpretation

* [Information.lean](formal/Information.lean) defines scenario equality constraints and their projection from a deterministic policy; ordered infima; strict stopping and weighted coverage; nonpositive expected penalties; historywise centering and the debit for a uniformly bounded bias. The weighted proof accepts pointwise upper enclosures of baseline cost and fallback floors. A caller must independently supply the same admissible baseline contract and original measure. No probability of deployment savings follows.
* [Viability.lean](formal/Viability.lean) gives an explicit contingent plan type, robust recursion, both directions of finite-horizon equivalence, and budget nesting. Classical choice supplies legal responses and off-path default branches in the mathematical existence argument. Public call and observed successor index a continuation. Time, history-dependent obligations, remaining budget and all other sufficient state must be observable/available at the relevant action. A hidden disturbance is never used to distinguish two identical successor observations. Kernel membership can become physically vacuous if one silently empties mandatory call or disturbance sets. Their engineering meaning is part of the contract.
* [Witnesses.lean](formal/Witnesses.lean) establishes exact costs for the two-stage game by kernel evaluation, along with threshold, weight, information-order and baseline controls. The intentionally failing [FalseVariants.lean](formal/FalseVariants.lean) asks for nine false propositions and is compiled separately. In the final negative build Lean reports that each is false. Development initially encountered a parser keyword, universe inference failure, and opaque rational comparison reduction. [Raw development diagnostics](results/development.log) retain those attempts. The final negative rational-sign controls use integer/positive-scaled equivalents plus positive rational witnesses.
* [Infimum.lean](addendum/Infimum.lean) is an explicitly labeled post-core formal extension. It converts uniform weak duality with bias debit into a real-valued infimum inequality under a finite lower bound. The integrability of each chosen penalty need not supply that bound across an infinite relaxed domain. For R={z≤0}, a singleton original policy z=0, F(z)=−1 and penalty M(z)=z, the relaxed penalized values fill (−∞,−1]. An extended-real infimum is −∞. Mathlib's totalized real sInf returns zero outside its bounded-below hypotheses here, and its uncontrolled use would produce a false floor. Finite W07-A has bounded finite data.
* [correspondence.py](correspondence.py) recalculates each A prefix's branch distribution using released leaf masses and probes the actual penalty implementation for every available action and feasible state. It verifies the issued conditional masses, cost ordering and penalized floor. For E, it rederives each commanded action mask from the specified integer physics and all integer protected-load values 18 to 48, exact terminal conditions, information order and successor table. It checks the 72-hour pre-observation occupancy equations and adjacent-budget nesting. The checker was run after the engineering freeze as an additional specification audit. These checks establish finite implementation correspondence on the checked instances. The Python source, MILP translator, forecast generator, machine arithmetic and field measurements are outside the Lean kernel.
