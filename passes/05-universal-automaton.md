# Pass 5 · Proposition I.1 and the universal automaton

**November 24, 2026.** This pass examines pp. 48–50 of Claude (Anthropic), *VP ≠ VNP Over Every Field*, in the [pinned edition](../source-lock.json). The questions are whether a program and its simulation have the same number of accepting runs, whether their weights sum to the same ring element, and how large the exact tape length must be. These questions have different answers.

## Run multiplicity

**Finding.** The published implementation can turn one accepting program run into zero accepting pointer traces. The sentence on p. 50 claiming exactly one accepting machine run for each accepting source run needs a qualification. The numbered proposition on p. 49 requires equality of weighted values.

**Counterexample using a canonical program.** Work over the integers. Give the empty bitstring the named generator −1, and give all other names weight zero. On the nil argument, evaluate a weight instruction whose argument quotes the bitstring containing a single false bit. The quote costs one step and the weight instruction costs one. The source accepts once with output nil, empty tally and weight zero. The input is therefore 2-plain. In the pointer interpreter, a name is read one bit at a time against the prefixes of the supported names. The only supported name is empty, so the first false bit has no outgoing rule. This branch has no accepting pointer trace. Both contributions to the value are zero. The example uses a weight lookup, which multiplies the run weight. The distinct instruction for recording a name would append to the tally. [Source evaluation rules](../primary/vp-vnp/NS1/Machine.lean#L243) · [Prefix table](../primary/vp-vnp/Nc/Uni/Rules.lean#L27) · [Missing-prefix branch](../primary/vp-vnp/Nc/Uni/EvalU.lean#L251) · [No-step rule](../primary/vp-vnp/Nc/Uni/PM.lean#L361)

**A positive multiplicity check.** Apply “first subtree” to a guessed bit. Both alternatives now return nil, cost two, have an empty tally and weight one. The source list contains the identical resulting record twice. The pointer machine distinguishes the first guess rules and the trace sum takes a disjoint union for those different first steps. The total is two in the integers and zero in characteristic two. Thus duplicate outputs survive this construction, while a ring-valued answer alone cannot recover the number of source runs. [Source guess and projection](../primary/vp-vnp/NS1/Machine.lean#L230) · [Pointer guess](../primary/vp-vnp/Nc/Uni/EvThm3.lean#L133) · [Disjoint trace sum](../primary/vp-vnp/Nc/Uni/PM.lean#L332)

## Preservation of weights

| Interface | What the source establishes |
|---|---|
| Program → pointer machine | The source value is a sum over an accepting **list**, including repeated occurrences. The pointer proof identifies that value with a sum of products of rule weights over valid accepting traces. Plainness requires all runs to halt and every accepting run to have an empty tally and cost ≤τ. This justifies ignoring nonempty tallies. Even recording the empty name would produce a list with one entry. A branch of weight zero may disappear as in the example above. [Plainness and value](../primary/vp-vnp/NS1/Accel.lean#L25) · [Weighted simulation](../primary/vp-vnp/Paper/UniversalSteps.lean#L84) |
| Pointer trace → matched encoding | Here there *is* a weight-preserving bijection. The construction produces a matched witness for each valid accepting pointer trace. A matched witness decodes to a valid trace, and two witnesses decoding to the same trace coincide. Address width, register values and sorted load records constrain the guesses. The finite sum uses injectivity and checks the product of rule weights term by term. [Existence](../primary/vp-vnp/Nc/Uni/Exist.lean#L26) · [Uniqueness](../primary/vp-vnp/Nc/Uni/Trace.lean#L308) · [Reindexing the sum](../primary/vp-vnp/Paper/UniversalSteps.lean#L43) |
| Matched encoding → matrix automaton | The formal series sums the weights of witnesses with the same channel contents. Matrix products and the sum over matched letter sequences realize the same scalar. This establishes equality after summation. It does not establish a bijection between source runs and individual matrix-state paths. A letter string spelling the input on the input channel alone still meets the matching condition. A leading idle followed by a nonempty active word gives zero coefficient in this construction. Thus the literal set of all matched strings includes irrelevant terms. [Definition of matching](../primary/vp-vnp/Nc/Tape/Run.lean#L24) · [Sum over witnesses](../primary/vp-vnp/Nc/Sort/RunVal.lean#L41) · [Terminal padding](../primary/vp-vnp/Nc/Tape/ProgRun.lean#L106) |

**Recommended reading of p. 50.** On a plain input the simulation preserves the sum of accepting weights. Each surviving valid pointer trace has a unique matched witness of the same weight. At the final matrix stage the assertion used by the proof is equality of the total coefficient.

## Exact time bound

Fix the finite-support generator table θ. The automaton and a constant C are chosen once for that table, before quantifying over the instance z, the accepting cost bound τ, and the tape length t. Put s=|z|, the number of tree nodes, and lg(x)=⌊log₂ x⌋+1 for positive x. The input is the preorder word of length s. The separate end mark in K.3 belongs to the polynomial word encoding. [Input length](../primary/vp-vnp/Nc/Dl/Cut.lean#L20) · [Quantifier order](../primary/vp-vnp/Paper/Universal.lean#L29)

1. **Pointer work.** With M the maximum bit length of a supported name, every valid accepting pointer trace has length at most T=3s+(40+2M)τ+10. M is fixed by θ. The bound on τ applies to accepting runs individually. [Pointer bound](../primary/vp-vnp/Nc/Uni/Bounds.lean#L35) · [Finite trace set and bound](../primary/vp-vnp/Paper/UniversalSteps.lean#L84)
2. **Tape contents.** For a trace of length u≤T the formal address-width parameter is determined by the bit size of u+1. The implementation globally checks guessed loads against allocated records and sorts by key. There are O(T) steps and records, O(log(T+1)) bits per record, and O(log(T+1)) sorting passes. The explicit tape-content bound is at most (50+b)(T+1)(L+1)² with L=bit-size(T+1) and b a fixed alphabet cardinality. Thus one-side tape contents fit a budget t₀ of order (s+τ)lg²(s+τ). [Width and trace](../primary/vp-vnp/Nc/Uni/Trace.lean#L203) · [Exact length](../primary/vp-vnp/Nc/Uni/LenU.lean#L177) · [Bound](../primary/vp-vnp/Nc/Uni/Bounds.lean#L37)
3. **Exactly t letters.** The matrix construction allows one terminal idle suffix of the necessary length for each contributing active word. Padding preserves its coefficient. Two tape sides, input length s and the positive-length guard yield the sufficient inequality 2t₀+s+1≤t. Since s≥1, the final constant absorbs both the additive terms and the change from lg(s+τ+2) to lg(s+τ). This proves the value identity for **every** integer t≥C(s+τ)lg²(s+τ). It describes the length of the encoded computation. Computing the sum of all matrix products on a deterministic machine is a separate cost. [Padding identity](../primary/vp-vnp/Nc/Tape/ProgRun.lean#L70) · [Exact-length theorem](../primary/vp-vnp/Nc/Tape/ProgRun.lean#L258) · [Final estimate](../primary/vp-vnp/Paper/Universal.lean#L39)

**Independent derivation of a sufficient constant.** Take x=s+τ≥1 and a=51+2M. Then T+1≤ax, and the elementary bit-length inequality gives L+1≤(lg a+2)lg x. Substituting in the contents bound gives t₀≤D x lg²x, with D=(50+b)a(lg a+2)². Since s+1≤2x lg²x, choosing C=2D+2 covers the exact tape threshold. This checks explicitly that C depends only on the fixed machine and generator table. The [Lean arithmetic check](../checks/pass05_time.lean) independently expands the exact expression for tU from LenU.lean and proves the majorant for all nonnegative b,T,L. It also proves the final padding inequality.

## Effect on the lower-bound argument

**K.3 consumes the scalar.** For H≥32 and sufficiently large v, take τ=v^H and s≤v^(H−32). Then s+τ≤2v^H, and lg(s+τ)≤(H+1)lg v at the admitted scales. The inequality 2C(H+1)²lg²v≤v lets one common t=v^(H+1) work for every eligible z. The word polynomial has degree at most n=v^(H−32)+1 including its end mark. K.3 requires its evaluation to be the image of the weighted program value in the target field. An omitted zero-weight run does not change that equality. J.3 also invokes the value theorem. We found no dependency of either call on raw accepting cardinality. [K.3 call and domain](../primary/vp-vnp/Paper/Circuit.lean#L68) · [K.3 time arithmetic](../primary/vp-vnp/Paper/Circuit.lean#L118) · [J.3 call](../primary/vp-vnp/Paper/Cuts.lean#L108)

**Separate encoding qualification.** Appendix Q, p. 69 discloses that Lean decodes an opcode by the length of a tree’s right spine. If a reader interprets the p. 49 prose as requiring literal equality to a canonical unary numeral, the tag consisting of a non-nil head and a nil tail would be invalid on that reading and would decode as opcode 1 (identity) in Lean. Over the integers that can distinguish failure (value zero) from identity (value one). Canonically encoded programs round-trip. The weight-zero counterexample above uses a canonical opcode and is independent of this interpretive issue. [Decoder and round trip](../primary/vp-vnp/NS1/Machine.lean#L161) · [Appendix Q, p. 69](../primary/vp-vnp/paper.pdf#page=69)
